# 个人面容与背景的技术边界（2026-09-24）

当前 `portrait.gaussian.ply` 是一份**整场景** 3DGS。训练将房间与面容放在同一套高斯中；`face_regions.json` 只包含正面帧的矩形检测框，用于提高训练时面容区域的损失权重。导出的 PLY 没有人脸、头发、耳朵与背景的逐高斯标签。因此目前无法仅凭屏幕坐标、深度阈值或离中心距离，安全地把背景压暗而保证所有视角的面容不受影响。

现有真机资产有 92,715 个高斯；留出视角的全图 PSNR 为 20.65 dB，正面面容区域 PSNR 为 21.10 dB。相机位姿覆盖约 -24.3° 到 +18.7°，侧面质量记录为 poor。这些数值只证明目前的正面附近显示链路成立，**不证明每个角度都准确**。[实测记录](evidence/reconstruction-e2e-20260924.json)及[重建训练](../backend/reconstruction_train.py)可复核。

本轮保留原始 PLY 和面容像素。个人模型页只调整原本透明的画布底色、按钮与文字所在的界面层；不对屏幕上的脸施加固定上下渐暗、径向裁切或整体滤镜。空主页及等待阶段的星光为装饰，不对应重建点位。

后续若要真正压暗杂乱背景，应在 Windows 重建端增加可验证的语义分层：

1. 在多视角源帧上生成包含脸、耳朵、头发与颈部的高质量轮廓，并检查侧视遮挡与跟踪一致性。现有 Haar 矩形不能作为最终分割标签。
2. 将各视角轮廓经已恢复的相机位姿关联到高斯，训练或统计逐高斯的主体概率；置信度不足的高斯保持原貌。保留原始 PLY，另产带版本及校验值的语义资产。
3. 在渲染时只降低高置信背景高斯的亮度或饱和度，主体高斯不变。必须核对多视角遮挡排序与半透明边缘，避免发丝、耳廓和侧脸出现断层。
4. 用参与训练和留出视角的正面、左右两侧逐帧对照原图与原始 3DGS；核对主体边界、眼鼻唇细节与侧面覆盖。未达到质量门槛时自动回退原始 PLY。超出采集角度的视图不能宣称准确。

[gsplat 官方光栅化接口](https://docs.gsplat.studio/main/apis/rasterization.html)支持深度及多维特征渲染，可用于验证逐高斯语义；[GaussianEditor 论文](https://openaccess.thecvf.com/content/CVPR2024/papers/Chen_GaussianEditor_Swift_and_Controllable_3D_Editing_with_Gaussian_Splatting_CVPR_2024_paper.pdf)说明从多视角二维分割向高斯赋语义标签的思路。这些是可研究的技术路线，不是本工程已集成或已通过真机验证的能力。
