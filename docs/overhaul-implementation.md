# SELF 本轮增量改进与未完成边界

2026-09-22。基于用户最新要求及已完整读取的 `SELF_HarmonyOS_Native_DeepSeek_Codex_20260922.md`；旧 ArkWeb 主渲染规定不再叠加。本地 Git 基线为 `1587601`，既有代码、作品格式、包名和用户配置保留。

## 已落地的行为

- 新颜色、强度调整、换色和移除单层由真实模型产生候选。`SessionStore.authorize` 拒绝没有模型来源及快照标识的新计划。圈选和云端发送许可均不等于修改授权。撤销、重做已授权历史、取消和恢复原图在本地可用。
- 不明确的局部意愿先询问；点击“想试一点变化”不再直接生成一个红色色块。模型只选择已实现的数字预设和离散强度，原生引擎执行像素修改；这不是生成式修图、真实化妆品功效或任意形变。
- 当前窗口宽度达到 840 vp 时使用宽屏构图。镜面保持同一 XComponent，常用操作浮在画面底部；对话卡位于圈画范围旁并限制在窗口内。手机保留紧凑的底部输入和工具入口。手写笔事件自动进入圈画，触摸可点击圈画或直接旋转；二指缩放取消未完成线条。
- 新操作保存 `compositingVersion=perceptual-v2`。圈内距离羽化不扩大授权范围；数字混色保留原图明暗、收敛高光与暗部覆盖。旧操作没有该字段时仍走旧算法，保存的保护锚点也保留各自版本。
- 修改先通过原生像素检查，再提交状态和账单。成功后约 650 ms 渐变显现；关闭柔和运动会停止此动画。导出及模型快照取得最终有效像素，不捕捉过渡帧。动画初始化失败不会撤回已成功的业务提交。
- 新增相机视频采集、私有视频列表和删除。系统 CameraPicker 明确由用户启动；成功返回后私有 MP4 与元数据写入 `files/captures`，不自动上传、不替换当前面容。模拟器相机目前未返回有效结果，实际录制/保存尚未验收。
- 接入一份大陆渠道事实资料库。模型回复中的产品 ID 必须来自本次检索；卡片只展示该回复实际引用的条目，默认页面、普通对话不展示产品。新请求、圈选、取消、撤销/恢复和切换作品收起旧卡片。“这款/它/试一下”等连续请求携带上轮核验产品 ID，后端结合请求重新检索，不能丢掉产品身份转为通用染色。
- 产品从原 SVG 图改为独立原生 3D 画布，6 种原创近似包装、12 个瓶身/盖子 GLB。拖动旋转、约 850 ms 开合；右侧“要点、配方、来源”卡片堆叠展开。名称/规格与模型引用一致；关闭画布不改变面容、账单或已授权历史。产品几何、材质和开盖方式均为外观示意，未测量真实 SKU，不能当成包装复刻。
- 产品特定修改在前后端拒绝无标定的通用染色。未知配方、浓度、物理参数和功效标定保持空值。**产品参数驱动的真实上脸修改未完成**：现有公开渠道名称/规格不构成效果参数，不能以提示词、插值公式或视觉动画补造证据。

## 本轮修复过的失败

- V1 状态中的间接 getter 没有可靠触发宽屏分支，改为显式响应式状态并核对窗口日志。
- 宽屏启动触发布局尺寸变化，EGL 返回 `12301`。现在在渲染线程同步 NativeWindow 缓冲尺寸并重建 EGL surface，保留上下文、资产和视角；实际平板重试通过。截图和日志仍保留失败版本。
- 旧像素脚本把照片圈选数量固定为手机的 45 texel，平板同一归一化圈选得到 171 texel。改为独立检查二值、居中、矩形完整性和严格小于全图的范围，不把不同投影误判为损坏。
- 产品问答首次返回过长，严格协议拒绝。缩小检索到相关条目并明确简短回复后，真实调用通过；没有放宽未知引用或真实效果限制。
- 自动化输入后误按返回退出页面、通过传感器旋转后立即回转属于测试脚本问题；修正为读取输入内容、窗口方向接口后复测。最初失败证据保留。
- 复查发现多层旧操作需要复用整组开始时的亮度，而不能逐层重新计算。已恢复该规则；新增原生照片多层导出与独立 CPU 旧公式对照，16 个采样点的最大通道误差为 0。新操作仍使用 v2 规则。
- 持续测试曾把未变化的“已应用”文字误当重做已结束，过早打开氛围。调整为等待实际面板出现；初始失败记录保留。

## Remy、建模与格式：目前不能验收为个人重建

[Remy 官网](https://www.remy3d.cn/)说明产品定位；[Khronos 的 SIGGRAPH Asia 2025 材料](https://www.khronos.org/assets/uploads/developers/presentations/glTF_Gaussian_Splats_-_glTF_BOF_SIGGRAPH_Asia_Dec25.pdf)把 Remy 列为 3DGS 应用。它不是本项目可调用的开放重建 API，也没有提供已验证的私有文件契约。

本机商业 SDK 26.0.0.105 的 `hms/native/sysroot/usr/include/spatial/spatial_recon_interface.h` 声明：`HMS_SpatialRecon_IsSupport`、`PushARFrame` / `PushFrame`，仅 GS 模型，PLY / MP4 输出，API 23 起。输入要有图像、内参、位姿、时间戳，不能把一段普通 MP4 当成已有这些数据的 AR 序列。手机和平板模拟器的运行时探针都未能加载空间重建库，故没有启动伪重建流程。

当前原生编辑器接收带 UV 的静态三角网格 GLB 或平面照片。GS PLY 的高斯数据与网格 PLY、普通视频、带 UV 的 GLB 不等价，改后缀不能解决兼容。没有采用 Blender 自动建模；`.blend` 不是设备运行格式。

下一道真实完成门槛是取得支持 Spatial Recon 的真机并测出支持状态，验证带同步内外参的横移采集、真实面容重建、PLY 读回，以及高斯编辑对可见选区与保护区的语义。若这些不能成立，再比较可产出 UV 网格的重建路线。当前没有个人 3D 精度、成功率、遮挡补全或真机流畅度证据。

补充采用 [OLAY 京东自营旗舰店公开页面](https://olay.jd.com/view_search-404604-26670202-99-1-24-1.html)的名称、页面标注规格及系列导航，登记 8 条 **渠道条目**。其中含系列、套装、多变体条目，不能算成 8 个已核实完整 SKU；库存、完整在售覆盖均未验证。第六代超红瓶与历史第五代信息分开，不能合并配方。没有用美国或香港版本替代大陆配方。

规范源为 `shared/products/olay-cn-catalog.json`；`scripts/build-product-catalog.py` 生成 ArkTS 数据，后端读取同一源。用户否定的六张 SVG 已退出产品 UI。`scripts/build-product-models.py` 自主生成 12 个带嵌入贴图的静态 GLB，运行时对独立盖子做变换，不依赖 Blender。Arial 仅用于本机生成原创文字贴图，字体文件未分发；没有下载官网产品图片或复制官方包装图形。资产清单与哈希在 `rawfile/products/3d/manifest.json`。品牌全量产品清单、批次/备案一致的 INCI 和可用于模拟的实验标定仍缺失；无法承诺“全部产品参数完全正确”。
