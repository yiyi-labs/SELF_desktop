# 自动引导、透明线条与完成条件 · 2026-09-23

## 当前能否建模

**仍不能生成用户自己的完整 3D 面容。** 两个问题分别存在：

1. 当前 API26 平板模拟器的真实运行查询仍为 `libraryLoaded:false / available:false`；系统路径也未找到重建、GS 渲染和编辑模块。Windows 相机预览能运行，不意味着模拟器包含 Spatial Recon 的端侧算法。安装商业 SDK 的编译声明不会补齐设备系统实现。
2. SELF 已有 Native 重建任务控制器，但真实 AR 位姿/相机采集、GS 载入主界面、质量验收及贴脸精细编辑仍未接通。换真机也不会自动完成这些应用代码。

官方存在 [HarmonyOS 7 API26 端侧 3DGS 课程](https://developer.huawei.com/consumer/cn/training/course/live/C201785722331155857)和 [GS 渲染接口](https://developer.huawei.com/consumer/en/doc/harmonyos-references/spatial-recon-spatialrender)。本轮再次尝试访问官方简介页时正文获取超时；未把第三方转载的支持表当作最新官方兼容保证。以上设备结论来自当前平板实测，不推断未来所有镜像。

## 已改动并安装

- 进入全屏预览即出现居中的人物／移动镜头线条，不再等待“开始录制”。
- 移除引导底板、背景模糊、边框、手机示意填色和全屏渐变遮罩；线条之间直接透出相机画面，文字仅保留轻微投影。
- 移除拍摄／停止按钮、录像计时及 30 秒自动结束逻辑。当前没有完整建模流程，不把自动录像替代建模。
- 预览专用路径不准备 AVRecorder、不创建 VideoOutput 或空 MP4。原有录像服务和历史采集仍保留，供既有记录及独立测试使用。
- 连续稳定运动判定不再依赖 `recording`。持续横移／相对转向后小圈收拢并跟随鼻尖；抖动不触发，丢失后重新寻找。这是二维检测与关联，不是真实三维皮肤锚点或身份识别。
- 修复动画在首次布局前跳到终点的问题：首帧建立后再启动往复运动，离开时清理延迟任务。
- 进入即查询重建能力，底部明确显示“本机暂不能建模 · 可体验面容跟随”；真机查询支持时仍提示应用流程未接通。返回和镜头切换保留。

## 何时才算完成

用户不应手动判断什么时候停止采集。完整流程必须区分以下事件，不能靠固定秒数的动画：

| 阶段 | 系统应判断的条件与提示 | 当前状态 |
|---|---|---|
| 寻找与跟随 | 有效单人观测、连续稳定运动后小圈跟随；失联重新寻找 | 已接入；真人贴合精度未验收 |
| 采集足够 | 真实 AR 位姿/标定有效；部位覆盖、清晰度和曝光合格，必要视角无缺失；提示“视角够了，正在生成你的 3D 面容”，自动结束采集并开始重建 | **未接通**；二维鼻尖角度、固定帧数或倒计时不能代替 |
| 重建完成 | SDK 成功回调后进入保存检查，不能先提示成功 | Native 控制器已有，真实输入未联调 |
| 个人模型完成 | 保存成功、GS 有效且可加载；原始/留出视角核验本人细节，资产登记成功；提示“你的 3D 面容准备好了”，自动退出采集并显示本人模型 | **未接通、未验证** |
| 不足或失败 | 跟踪丢失、视角不足、资源限制或质量不合格时补采／明确失败，保留旧面容 | 当前仅有能力不可用提示；完整补采与热状态调度未接通 |

正常完成不需要用户按暂停，返回是取消。耗时不能推动提前完成、降质、生成式补脸或用示例头像替换。完成提示必须由通过验收的真实结果触发，当前版本不会伪造这一提示。

| 检查 | 结果与边界 |
|---|---|
