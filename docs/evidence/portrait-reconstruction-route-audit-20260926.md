# SELF 人像与环境重建路线复核（2026-09-26）

本记录是对当前工程与一段已授权历史视频的隔离探针，不是新个人模型通过验收的声明。本轮没有替换平板资产、签名、上脸编辑、故事或传输协议。私有视频帧和探针资产位于忽略目录；此文只含数值和方法。

## 当前真实链路与缺口

`reconstruction_worker.py` 以时间桶抽 160 帧，`reconstruction_face.py` 生成头部掩膜，`recover_cameras` 却在**未排除人物的整幅图**上运行 COLMAP。`reconstruction_pose.py` 用 MediaPipe 的规范 468 点和 PnP 给面部训练视角做粗补偿，不能视为本人真实 3D 形状或可靠头部运动真值。`reconstruction_train_joint.py` 使用两类高斯、两套视角，并在脸训练时把背景透明度置零、在环境训练时把脸置零；导出虽是一个 PLY，训练时并没有共同计算遮挡。现有质量门槛也分别检查脸与环境，不验证最终合成的颈肩连续性和背景遮脸。`reconstruction_scene.py` 的环境掩膜只供播种和旧实验使用，未进入当前 `recover_cameras` 的特征提取。

`portrait_preview.py` 和 `viewer-gs/main.js` 继续消费标准 PLY 与 `portrait.view.json`。因此重建侧可以改变内部相机/运动优化，但若切换为静态背景相机，`reconstruction_view.py` 目前依赖“脸部 COLMAP 三维轨迹”的取景逻辑也必须随之修改；否则静态背景 SfM 没有脸部轨迹，会在取景阶段失败。

## 固定输入与依赖

本次难例视频 SHA-256 为 `7ac189eb49e05c83220addf16c1fabe325ef35e32d8ffd7e4c5af4824777e4cf`，时长 65.339 秒，1963 帧，文件流 1920×1080、旋转元数据 90°；OpenCV 实际输出的帧是 1080×1920。现有抽帧 160/160 检出脸，头部区域宽度约 533–725 px（中位 613 px）。当前代码的清晰度打分却强制将竖向帧压到 480×270；这属于选帧几何错误风险，**尚未做同片重训对照**。

本机 WSL 环境：PyTorch 2.8.0+cu128、gsplat 1.5.3、PyCOLMAP 4.2.0（`has_cuda=False`）、MediaPipe 1.0.1；PlayCanvas 锁定 2.22.4。CUDA 训练可用不表示 COLMAP 特征、匹配走 GPU。原实验记录的约 255 秒中，解码与筛选约 29.65 秒、MediaPipe 约 43.5 秒、COLMAP 约 111.79 秒、GPU 训练约 63.61 秒。此处是历史同片旧配置计时，不能与缓存探针相加或代替新全链路计时。

## E0：格式与遮挡可行性

- `backend/probe_gs_contract.py` 生成四个颜色、旋转、长短轴、前后深度不同的合成高斯，测试三个视角。gsplat 内存图与 PLY 回载图最大像素差 0；log-scale、logit-opacity、高阶 SH 系数往返最大差 0。
- `viewer-gs/tests/ply-contract.test.mjs` 使用项目安装的 PlayCanvas 2.22.4 PLY 解析器，核对四个 splat、中心、旋转、各向异性尺度、DC/高阶 SH 字段及透明度，通过。此探针只验证 **C 的字节解析与语义**，尚未比较 PlayCanvas 的浏览器 GPU 实际画面或鸿蒙同文件画面。
- `backend/probe_visibility_channels.py` 在锁定 gsplat 上用同一次 5 通道绘制计算 RGB、环境贡献和人物贡献。人物在墙前时中心 `(q_bg,q_person)=(0.0752,0.918)`；墙在人物前为 `(0.918,0.0752)`；边缘混合两者均非零，贡献损失对几何有梯度。证明同一遮挡排序下的归属约束在当前版本可行；不是实际训练成功。

## E1：静态背景相机探针

`backend/probe_static_camera.py` 用已安装的六类 MediaPipe 分割，从整个人的头发、皮肤、衣物、配饰生成 COLMAP **特征排除**掩膜；不修改原片 RGB 或训练掩膜。逐个读取 PyCOLMAP 数据库验证实际提取的特征：全 160 帧 324399 个关键点中，人物排除区内 **0 个**。排除面积中位 40.43%。

| 隔离方案 | 注册/输入 | 静态点 | 重投影中位 | 关键结论 |
| --- | ---: | ---: | ---: | --- |
| 原生产混合人物与环境 | 160/160 | 20457（混合） | 未作为本轮静态比较指标 | 移动人物可能牵动相机 |
| 整人物遮罩 + 逐步 SfM，隔帧 | 53/80 | 1982 | 0.590 px | 中间视角缺失 |
| 整人物遮罩 + 逐步 SfM，全帧 | 106/160 | 3194 | 0.632 px | 连续缺 54 帧；纯静态 2D–3D 补定位新增 0 帧 |
| 遮罩略窄，阈值 0.38 | 106/160 | 3274 | 0.632 px | 没补视角，另有 5423 个点进入原保守不确定带，故不采用 |
| 同一遮罩图 + 未标定全局 SfM | 160/160 | 3419 | 0.624 px | 轨迹与旧混合模型大幅不同，不能只看注册数 |
| 视图图标定焦距 + 全局 SfM | 160/160 | 3268 | 0.589 px | 焦距约 1181 px，需继续审查中间段的真实视差 |

最后一方案的静态三角角度中位 1.637°、10 分位 0.240°，有 840/3268 个点 ≥3°。与逐步静态模型共同的 106 帧经 Sim(3) 对齐，中心残差中位 0.0146 个该模型场景单位、90 分位 0.0332，方向中位 0.341°、90 分位 0.384°；这是**共同视角的一致性**，不证明缺失段深度正确。缺失段附近全局相机相邻位移中位明显增大。全局静态模型与旧混合人物模型的 160 帧比较，中心残差 90 分位 3.2005 个混合模型单位，方向 90 分位 13.339°；旧模型不是独立真值，差异仅提示高风险。不能将全局的 160/160 注册当成 E1 完成。

## 最小生产实施顺序与验收闸门

1. **先修输入契约**（`reconstruction_worker.py`）：保存真实时间戳、实际解码方向、选帧清单及输入/配置哈希；竖屏帧不拉伸评分。分别记录背景关键帧与人像训练帧，以及真实脸宽和角度覆盖。保持当前作品读取不变。
2. **静态相机**（新增小模块，替换 `recover_cameras` 的求解输入）：整人物遮罩用于特征，先标定共享焦距并建立静态图；对全局 SfM 缺失/低视差段做逐帧静态特征和运动连续性复核。明确不可信区间，不用线性插值冒充已定位。经验证才将新相机传到后续流程。当前 E1 尚未通过。
3. **共享本人形状与受限运动**（`reconstruction_pose.py`）：规范脸仅作 PnP 初始化；拟合一套共享身份几何与每帧有限头/上身运动，把头发、镜框、衣物及颈肩连续绑定到观测支持的部位。FLAME 2023 Open 可做形状先验，但须先核验下载到的准确资产及许可；不能直接复用 VHAP 的非商业代码。先用少量点验证重投影、身份一致、参考帧恒等和颈肩变形，再开放 GS 训练。
4. **同一次遮挡训练**（`reconstruction_train_joint.py`、`reconstruction_scene.py`）：每帧把人物高斯的均值**与协方差**一起变换到静态场景，在单一相机中把全部高斯共同排序绘制；用本轮已验证的贡献通道约束错误背景遮脸和人物漏到背景。保留衣服与连续颈肩，不做脸/房间双相机合成。所有分裂/裁剪同步继承语义、绑定和来源索引。
5. **真实细节窗口**（同一训练器）：全景低分辨率、人脸原始采样 ROI、颈肩衣领 ROI 交替。ROI 调整内参但不裁去可能投影进窗口的其他高斯；固定画面尺寸对照真实眼镜框、眼鼻唇边界。脸、环境、颈肩与最终共同绘制分别设门槛，PSNR 不能单独放行。
6. **参考状态导出**（`reconstruction_view.py` 与导出侧）：选真实清晰帧，固定人物和环境到统一世界坐标，导出单一静态 PLY；高阶 SH 的方向基底、视角 sidecar 和编辑索引映射需分别复核。继续使用现有 PlayCanvas/HarmonyOS 格式，失败候选不覆盖用户作品。
7. **最后压时间**：测解码、检测、特征、匹配、相机、人物拟合、训练、导出各段冷/热耗时及进程级峰值显存。当前 8GB、120–180 秒仅为目标，不是已通过。

E2–E6 当前均**未完成**。当前代码不适合在未解决 E1 可靠性与统一人物运动之前，只继续调高权重、增大点数或删背景。原视频只有已拍到的角度和细节可作为真实监督；若中段静态背景视差和目标侧面确实不足，必须如实报告最小补拍需求。
