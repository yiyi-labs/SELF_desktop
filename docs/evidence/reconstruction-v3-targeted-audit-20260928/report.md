## 4. 360步到底启用了什么

### 4.1 optimizer确实连接源参数，但没有连接全部原定能力

`FreeComponent`的源参数顺序为offset、log_scales、quats、opacity、sh。B检查点保存了param-group名称；C没有名称，但实际顺序与模块注册顺序对应。直接读取Adam检查点，各组step及一阶矩非零，排除了“只改临时张量，优化器没有更新源参数”的怀疑。

| 参数 | B：hair / accessory LR；真实step | C：room LR；真实step | 激活与实际变化 |
|---|---|---|---|
| offset | .005；320 | .002；360 | base+tanh(offset)×max_offset；hair位移L2中位2.740mm，accessory1.067mm；room世界位移见上 |
| log_scales | .001；360 | .0008；360 | exp激活；hair比例中位1.0646，accessory1.1483；room约1.0016 |
| quats | .0003；360 | .0002；360 | 前向归一化；检查点变化且Adam矩非零 |
| opacity(logit) | .004；360 | .004；360 | sigmoid；hair最终中位.53945，accessory.62564；room.27056 |

### 4.3 密度与门禁

本机gsplat1.5.3 `DefaultStrategy`真实签名的refine_start_iter是500；但v3 B/C根本没创建该策略，也没有调用step_pre/post_backward。其refine_start/stop/reset是**不适用**，不是“360步尚未到500，后面自动会启用”。加到501仍不会有split。
